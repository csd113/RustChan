# TUI upgrade report

Work is on `TUI-upgrade`. No commits, pushes, release changes or Cargo dependencies were added. The working tree was clean before starting.

1. **Architecture before/after.** Previously, four screens and all rendering, dialogs, theme/formatting and disk-log loading lived in a roughly 2,000-line `dashboard.rs`; statistics lived with terminal lifecycle management. The console now separates lifecycle (`mod.rs`), keyboard input (`input.rs`), navigation/modal state (`state.rs`), bounded form editing/validation (`forms.rs`), operation execution (`wizard.rs`), background sampling (`stats.rs`), safe read-only task/runtime models (`telemetry.rs`), bounded history (`history.rs`), list projections (`browse.rs`), shared primitives (`widgets.rs`), and screen/modal renderers. Visual/navigation regression tests have dedicated files. Existing administrative and server business logic is preserved.

2. **Major UX changes.** Compact persistent product/version/status header, six destinations, discoverable help, contextual footer hints, attention counts before overview panels, active/queued/failed work, searchable/sortable content, searchable/filterable logs, deliberate detail views and explicit unavailable/loading/empty states. The header warns about collection, worker/media and tracked database-maintenance failures. Successful database queries are not presented as an integrity check.

3. **Screens/functionality.** Overview retains transports, live onion address, traffic/content/storage/memory and media activity. New Tasks shows durable worker and tracked maintenance work. Content retains the existing boards table and controls, adding search/sort/Enter details. Logs retains scrolling/pan/follow and adds text/severity filters, explicit pause and entry inspection. New System shows version/uptime, database/data/upload locations, tool capabilities, queue rejection counts, bounded administrator identities, moderation totals/recent events and media reconciliation observations. Configuration displays a nonsecret read-only allowlist, source/override context, actual runtime backup/FFmpeg settings and restart-scoped values.

4. **Task visibility.** Video transcodes, audio waveforms, thread-retention pruning and spam checks come from SQLite. Running/queued rows precede recent failed/completed rows; each state is capped at 40 with an omission indicator. Aggregate worker counts remain authoritative. Details include identity/type/item/state/attempts/creation/transition timestamps and meaningful availability limits. Existing maintenance-gate and database-maintenance trackers are surfaced, including terminal failures. Active backup creation phases show actual file/byte counters. Raw payloads, IP hashes and raw worker errors are excluded; diagnostics remain available through Logs/web admin.

5. **Metrics/history.** Existing actual request totals/rates/in-flight/active-IP and content/storage/media metrics are retained. New bounded history stores 120 measured request intervals, at least ten seconds apart, with actual elapsed duration, current/average/peak rates and a request-count sparkline. Manual refreshes cannot invent samples. Upload-tree size is cached thirty seconds; read failures display unavailable rather than zero. Runtime queue drops and media reconciliation counters are exposed without path labels. Active IPs are labeled as IP activity, not account/session counts.

6. **Keyboard model.** 1–6 and Tab/Shift-Tab navigate; arrows/J/K select or scroll; PgUp/PgDn and Home/End page; Enter inspects; Esc closes/clears/back; `/` edits a bounded literal filter; S cycles state/sort/level; P/F pause/follow logs; ?/H opens help and Esc restores its originating screen. C/A/D/X retain board/admin creation and confirmed thread deletion; R refreshes; Q confirms graceful shutdown; Ctrl-C stops immediately. Forms retain Unicode cursor editing, bounded paste, masked credentials, toggles and Ctrl-Enter/F2 submission. Held confirmation keys never authorize destructive work.

7. **Responsive behavior.** Overview stacks below 100 columns and wraps label values; content drops its side panel below 78; tasks drop side details below 110 and use compact columns below 68 table columns. Details and documents wrap at grapheme boundaries and scroll. Navigation/footer shorten on narrow terminals. The 44×14 minimum preserves interaction; smaller/zero dimensions show the resize fallback and reject hidden forms/confirmations. Critical IDs/status and full details stay accessible.

8. **Files changed.** Existing files substantially changed: `src/server/console/{mod,dashboard,state}.rs` and `src/server/server.rs`. Added: `src/server/console/{browse,content,dashboard_tests,dialogs,forms,help,history,logs,operator_views,state_tests,stats,telemetry,widgets}.rs`. No old administrative capability was removed; existing forms, execution, input safety, first-run setup, signal/terminal restoration, and headless behavior are retained. Added documentation: `docs/tui-audit.md`, `docs/tui-design-system.md`, this report. `Cargo.toml`/`Cargo.lock` are unchanged.

9. **Tests.** Console coverage increased from 32 to 47 tests (15 added). New coverage verifies navigation/help origin, modal search focus and bounded paste, stable task identity/paging/inspection, durable task transitions, actual maintenance/backup trackers, snapshot caps/order/failure propagation, padded log-level parsing, credential/control redaction, history bounds/counter reset/rates, populated/empty/error task layouts, long Unicode names and narrow header version/help, complete medium-width uptime/footer pairs. Existing tests now exercise all six destinations and resizing, preserve masked forms and destructive confirmations, and verify scroll access to history/help.

    Live pseudo-terminal QA used a temporary isolated database, 41 boards, six valid video jobs through a delayed real FFmpeg wrapper, an explicit failure fixture, and generated HTTP traffic. It exercised all destinations, state/text/level filters, large lists, empty filters, long names, details, masked forms, deletion/shutdown confirmations, help, graphs, pause/follow and resize at 120×40, 80×24, 60×18, 44×14 and the 40×10 fallback. Both monochrome and color output were inspected. The live pass caught and fixed header clipping, split footer pairs and padded log severity parsing. Source errors/unavailable states and maintenance/backup transitions are additionally exercised with deterministic tests. Generated PNG/text/raw-terminal evidence is ignored under `output/tui-upgrade-qa/`.

11. **Underlying limits.** Workers do not publish percentage, ETA, worker identity, reliable throughput or safe per-job cancellation/retry; the console states this rather than inventing values or mutating queue rows. Short scheduled cleanup operations lack lifecycle trackers. Backup progress has no start timestamp or reliable terminal failure state, so only active creation counters are displayed. Metrics are process-local, not persistent historical monitoring. Administrator identities are limited to the newest 25 with a full count; full account/moderation/backup/restore controls remain in authenticated web admin/CLI. Configuration remains intentionally read-only. No federation screen is invented for inactive legacy tables.

12. **Companion alignment.** Reproduce the concrete conventions in `docs/tui-design-system.md`: primary screen order, keys/search focus, semantic statuses, restrained panel/focus styling, task model, bounded history/log retention, confirmations, and responsive breakpoints. Keep RustPost-specific content/account workflows behind its own data/action adapter; share design conventions without introducing a direct project dependency.
